# 侧视头肩跟踪代码版本改动记录

_版本关系：服务器原始代码（000）→ 本地化基线（001）→ 当前跟踪改进版（002）。记录按日期和序号正序排列。_

---

## 📋 版本基线

服务器原始代码（000）是最初的侧视头肩检测与跟踪实现，包含 YOLO 检测、OSNet 外观特征、速度预测和两阶段 ID 关联。

本记录只记录两个增量版本：

| 版本 | 变更关系 | 主要目标 |
| --- | --- | --- |
| `2026-08-25_001` | 服务器原始代码 → 本地化基线 | 完成本地运行、中文路径兼容和同帧 ID 修复 |
| `2026-08-25_002` | 本地化基线 → 当前改进版 | 提升跨帧运动补偿、外观关联和批量运行能力 |

## 🔧 2026-08-25_001：服务器代码本地化与基础修复

### 路径和运行环境

- 将服务器上的输入目录、输出目录和模型路径替换为本地路径。
- 检测模型改为本地 `runs/head_v2/weights/best.pt`。
- 保留原服务器路径注释，便于追溯来源。

### 中文路径读取

- 新增 `imread_cn()`。
- 使用 `np.fromfile()` 加 `cv2.imdecode()` 读取中文路径图片，避免 `cv2.imread()` 读取失败。

### OSNet 外观特征

- 保留并恢复 OSNet 预训练权重加载。
- 对特征进行 L2 归一化，使用点积计算外观相似度。
- 增加本地权重缓存说明。

### 同帧重复 ID 修复

- 阶段二新建全局 ID 时，不立即写入全局历史库。
- 使用临时字典保存本帧新建的 ID。
- 当前帧所有检测处理完成后，再将新 ID 写入历史库。
- 避免同一帧后面的检测框立即匹配到刚创建的 ID。

### 可视化改进

- 增加智能标签摆放函数。
- 标签默认放置在检测框上方；发生重叠时依次尝试下方、框内或左右侧位置。
- 为标签增加黑色底纹，提高夜间红外图像中的可读性。

### 其他调整

- 保持 `CONF_THRES = 0.25`、`MAX_AGE = 8` 和原有运动-外观匹配逻辑不变。
- 仅调整注释、空白和导入顺序，不改变检测模型结构。

## 🚗 2026-08-25_002：运动补偿与跨帧关联改进

### 批量运行入口

- 增加命令行输入目录和输出目录参数。
- 未传入参数时使用默认序列。
- 支持按输入序列自动生成独立输出目录，便于多序列对比实验。

### 检测筛选和跟踪参数

- `CONF_THRES` 从 `0.25` 调整为 `0.6`，过滤低置信度头枕、反光等误检。
- 新增 `SPATIAL_R = 70`，作为外观失败时的空间兜底半径。
- 新增 `DIST_GATE = 80`，作为全局运动补偿生效时的阶段一位置门限。
- GMC 无效时，阶段一位置门限回退到 `150`。

### 轨迹外观特征

- 删除平均外观特征方法。
- 阶段一匹配改为在轨迹最近 5 帧特征中取最大相似度。
- 全局 ID 历史改为 `deque(maxlen=5)` 滚动画廊。
- 阶段二认领阈值改为随检测置信度变化：

  ```text
  0.76 + (1 - confidence) * 0.10
  ```

### 简化全局运动补偿

- 新增基于旧轨迹中心和新检测中心的全局平移估计。
- 当内点数量达到 2 个时，使用估计的整车平移预测目标位置。
- GMC 无效时，继续使用目标速度或全局平均速度预测。
- 增加漏检期间的 `missed_shift` 累计，用于目标恢复时的位置修正。

> ⚠️ 该实现是基于检测框中心的平移估计，不是完整的稀疏光流 GMC、卡尔曼滤波或仿射变换实现。

### 阶段一自适应匹配

- 不再固定使用 `0.7` 外观权重和 `0.3` 运动权重。
- 根据检测置信度计算 S 型权重，并将运动权重限制在 `[0.2, 0.5]`。
- 综合得分改为运动得分和外观相似度的自适应加权。
- 根据检测置信度调整目标速度更新比例。

### 阶段二全局认领

- 新增 `claimed_gids`，保证一个全局 ID 在同一帧最多被认领一次。
- 将阶段一已经匹配的轨迹加入已认领集合，防止阶段二重复抢占。
- 外观匹配失败时，增加基于预测位置的空间兜底。
- 如果全局 ID 已对应存活轨迹，则复用该轨迹，避免同一目标并存多条轨迹。

### 诊断和输出

- `update()` 增加检测置信度参数。
- 增加每帧 ID 列表、检测框坐标、置信度、阶段二决策和 GMC 内点日志。
- 图像底部显示全局平移和内点数量。
- 保留智能标签摆放逻辑。

## ⚠️ 当前版本边界

- 当前跟踪器仍是自定义两阶段关联器，不是完整的 Ultralytics BoT-SORT 或论文 MA-BOTSORT。
- OSNet 使用通用预训练权重，红外头肩裁剪图与训练域存在差异。
- `CONF_THRES = 0.6` 按已有序列标定，换用低光或高速模糊数据时可能漏检。
- 目标数量较少时，全局平移估计不稳定，应回退到速度预测。
- 当前记录不包含实验输出图片；输出图片属于可再生成的运行产物。

## 🎯 2026-08-27_003：实际人数对照功能

> 目的：快速判断跟踪计数（累计唯一人数）的准确度。在输入序列目录放置人工核实的总人数 txt，脚本读取后与跟踪累计值对比并显示。

### 实际人数 txt 格式

- 文件名：`total_registered.txt`（或 `actual_count.txt`），放在**输入序列目录**（`超员原图0729/<序列>/`）。
- 内容：`total_registered <N>`（也支持纯数字 `N`），N 为该车人工核实的实际人数。
- 由用户手工填写，需人工确认车辆真实人数。

### 脚本改动

- 新增 `read_actual_count(image_dir)`：读取序列目录下的实际人数 txt，解析整数；找不到返回 `None`（不显示对照，不影响原流程）。
- 主循环前读取实际人数并打印 `[INFO] 人工核实实际人数 = N`。
- 每帧结果图左上角在 `Total Registered Passengers` 下方新增一行：
  - `Actual: N  Diff: +d`（Diff = 跟踪累计值 - 实际人数）
  - 颜色随偏差变化：`Diff=0` 绿色（准确）、`|Diff|<=1` 橙色（小偏差）、`|Diff|>1` 红色（偏差较大）。
- 序列结束打印对比总结：`📌 人工核实实际人数: N，差值 +d（准确/偏差较大）`。

### 实测（序列 20260714151020365，实际 7 人）

- 跟踪累计 5，差值 -2（少计数）——量化了漏检导致的欠计数问题。

### 用法

```bash
python sideview_headshoulder_counter.py "F:/车辆超员检测项目数据集/超员原图0729/<序列>" <输出目录>
```

> 配合 `tracking_output/README.md` 的输出规则，批量跑 12 序列时每个序列放好 `total_registered.txt` 即可逐序列对比计数准确度。

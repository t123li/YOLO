## 修改动机

v3 实测 12 序列：精确 6、±1 有 5、≥+2 有 1（+1）。存在三类残余问题：

| 问题 | 现象 | 责任层 |
| --- | --- | --- |
| 欠计数 | 遮挡/小头漏检，每车 -1 | 检测召回 + 跟踪低分丢弃 |
| 过计数 | 头枕/反光误检被计入，曾 +2 | 检测误检 + 无生命周期 |
| ID 跳变 | 聚集时相邻目标 ID 互换 | OSNet 判别 + 贪心匹配 |

## 修改清单（v3 → v4）

### 1. 修复 OSNet 输入 BGR→RGB

- **位置**：`extract_feat()`
- **问题**：OSNet 按 RGB 预训练，但 `img_crop` 来自 BGR 图像（cv2.imdecode），喂入的是 BGR，特征系统性失真，外观判别力下降 → 间接导致 ID 跳变。
- **改动**：`extract_feat` 内先 `cv2.cvtColor(img_crop, cv2.COLOR_BGR2RGB)` 再进 transform。

### 2. 阶段一改用匈牙利全局匹配（治 ID 跳变）

- **位置**：`MotionCoherentTracker.update` 阶段一
- **问题**：原来按 score 排序贪心逐个抢，一个轨迹被抢后另一检测只能找次优 → 聚集时易串 ID。
- **改动**：构建代价矩阵 `cost[i][j] = 1 - score`（位置+外观加权，含窗口绑定/顺序约束过滤），用 `scipy.optimize.linear_sum_assignment` 做全局一对一分配。用大数 `BIG=1e6` 而非 `np.inf` 避免 "infeasible" 报错，分配后过滤掉落在 BIG 上的匹配。

### 3. 窗内顺序保持（治聚集 ID 互换）

- **位置**：`MotionCoherentTracker.update` 阶段一代价矩阵
- **问题**：聚集时两个相似头位置近、外观像，检测框抖动就把 ID 配到邻座。
- **改动**：同窗匹配时，若检测 rel_x 与轨迹 rel_x 差 > 0.35 窗宽则禁止（人在窗内 rel_x 跨帧漂移有限，差太大说明顺序错位）。利用"同窗乘客从左到右顺序基本不变（不换座）"的强先验。

### 4. 轨迹生命周期 Tentative→Confirmed（治过计数）

- **位置**：`MotionCoherentTracker.confirmed_ids/tentative_ids/total_count`
- **问题**：v3 `pred=len(gid_hits)`，新检测一出现就计数，头枕/反光单帧误检立即污染计数。
- **改动**：
  - 新轨迹 `hits=1` 为 **Tentative**（渲染标 `h{id}?`、橙色框），不计数。
  - 累计观测 ≥2 帧转 **Confirmed**（红色框），才计入 `pred`。
  - `pred = confirmed 数`；`tentative_ids()` 用于渲染区分。
  - 权衡：只出现 1 帧的真乘客（遮挡闪烁）不计入，会引入 -1 欠计数，但挡住了 +2 过计数——超员检测中防虚报优先。

### 5. 座位槽硬约束（治过计数，结构性）

- **位置**：`MotionCoherentTracker.update` 阶段二新建处 + 配置 `SEATS_PER_WINDOW = 3`
- **问题**：曾见单窗攒 4-6 个 ID（如 `20260715073655824` 窗 1 曾有 6 人）。
- **改动**：每窗允许的确认人数 ≤ 座位数（前/中/后窗各≤3）。窗满时，落在该窗的新检测**不建新 ID**（标记 `-1`，渲染跳过）。被抑制的检测在 `frame_gids` 用 `-1` 标记，`process_sequence` 渲染时跳过。

### 6. 高分/低分两级关联（ByteTrack 思想，治欠计数+过计数）

- **位置**：`process_sequence` + `MotionCoherentTracker.update`
- **问题**：原来 `CONF_HEAD=0.15` 过滤掉遮挡/小头的低分真检测 → 欠计数；同时低分误检（头枕）没区分 → 过计数。
- **改动**：
  - `predict conf=0.05` 多检，head 用 `CONF_HEAD=0.10` 收集。
  - 高分框（conf≥`CONF_HEAD_HIGH=0.35`）：允许新建轨迹。
  - 低分框：`allow_new=False`，只延续已有轨迹，未匹配上则不新建（丢弃）。
  - **后续调参**：发现"低分一律不新建"误杀了遮挡真乘客（欠计数 -2），改为"低分也建轨迹但靠生命周期确认"，最终统一确认门槛 2 帧。过计数由座位槽 + 生命周期治理，不靠提高确认门槛。

## 配置变更

| 配置 | v3 | v4 | 说明 |
| --- | --- | --- | --- |
| `CONF_HEAD` | 0.15 | 0.10 | 多检，召回遮挡/小头 |
| `CONF_HEAD_HIGH` | — | 0.35 | 高分阈值（可建新轨迹） |
| `PRED_CONF` | 0.2 | 0.05（predict） | 底层多检 |
| `SEATS_PER_WINDOW` | — | 3 | 每窗确认人数上限 |
| 匹配 | 贪心 | 匈牙利 | 全局最优一对一 |
| 计数 | `len(gid_hits)` | `confirmed 数` | Tentative 不计数 |
| OSNet 输入 | BGR | RGB | 修正特征失真 |

## 结果对比（12 序列）

| 指标 | v3（20260828_014） | v4（20260829_005） |
| --- | --- | --- |
| 精确（差0） | 6 | **5** |
| ±1 | 5 | **7** |
| ≥+2 | 1（+1） | **0** |
| 最差 | +1 | -1 |

差值：v3 `-1 +1 -1 0 0 0 0 0 +1 -1 0 +1` → v4 `-1 +1 -1 0 0 -1 -1 -1 +1 0 -1 +1`

**关键收益**：
- **无 ≥+2 的过计数**（+1 → 0，结构性抑制生效）。
- **ID 跳变大幅减少**：`20260714180408088` gid 0-4 全程稳定（早期版本每帧跳新 ID）。
- 代价：3 个序列从 0 → -1（生命周期过滤了只露 1 帧的真乘客），属"防过计数 vs 欠计数"权衡，超员检测中防虚报优先。

## 诚实说明

- **欠计数（-1）仍是检测召回限制**：recall=0.97 下剩余漏检是"完全遮挡的头"（物理不可见）或检测未框出。生命周期把"只露 1 帧"的真乘客也滤掉了，加剧 -1。
- **未做**：车 ROI 放大检测（报告里建议的欠计数手段，本次未实施）。
- **下一步候选**：① 若欠计数是主要矛盾，加车 ROI 放大 + 低分框"延续优先"细化；② 若需恢复"露 1 帧也计数"，可把 Tentative 但"位置/外观确定"的短轨迹也计入（需权衡过计数）。

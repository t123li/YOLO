## 详细修改历史

### v1（创建，commit `e93335c`）

- **内容**：D 方案首版，3 类检测 + 车窗跨帧跟踪 + 运动补偿&OSNet 人跟踪 + 窗口绑定。
- **车窗跟踪**：用"车锚定 relx"（窗口中心相对车框归一化 x）做跨帧匹配。
- **结果**：窗 ID 严重不稳定（relx 依赖车框，车框噪声 → relx 漂移 → 窗 ID 重建 → 人绑定全乱），单序列 21 差 15，废弃。

### v2（调试迭代，commit `e93335c` 后未单独提交）

- **窗 ID 稳定**：改"中位数位移补偿 + IoU"匹配，窗 ID 稳定（f0-f6 全程 [0,1,2]）。
- **人关联**：加窗内 rel 坐标（同窗用 rel 距离、异窗用全局像素距离），解决透视投影下 RANSAC 失效。
- **结果**：12 序列精确 5、±1 有 5、≥+2 有 2（最差 +2）。对应 `tracking_output/20260828_002~004`。

### v3（commit `cac6a8c`，**最优计数基线**）

- **车窗 ID 物理稳定**：先判断车头方向（首帧贴边启发式 + 位移确认），用"离车头槽位"匹配，前窗=槽0，中间插入新窗不影响。`20260714180408088` 前/中/后窗 ID 全程稳定。
- **首帧框窗**：首帧用启发式方向立即建窗。
- **每窗人数实时**：显示本帧落在窗内的检测数（非历史累计）。
- **pred 即时累计**：`pred = len(gid_hits)`（所有出现过的 ID），出现即计数。
- **结果**：`tracking_output/20260828_014`，精确 **6**、±1 有 5、≥+2 有 1（+1）。**准确计数最佳。**

### v4（commit `6882cf4`）

依据《车辆超员场景_跟踪计数问题分析与改进方案_20260828.md》做六项改进，针对三类问题：

| 问题 | 改进 |
| --- | --- |
| ID 跳变 | ① 匈牙利全局匹配（替贪心）② 窗内顺序保持（rel_x 差>0.35 窗宽禁止）③ 修复 OSNet BGR→RGB |
| 过计数 | ④ 生命周期 Tentative→Confirmed（min_hits=2）⑤ 座位槽上限（SEATS_PER_WINDOW=3） |
| 欠计数 | ⑥ 两级关联（predict conf=0.05 多检，高分≥0.35 可建轨迹，低分只延续） |

- **结果**：`tracking_output/20260829_005`，精确 5、±1 有 7、≥+2 有 **0**（无过计数）。ID 跳变大幅减少（`20260714180408088` gid 全程稳定）。
- **代价**：3 个序列 0→-1（生命周期把"只露 1 帧"的真乘客过滤了）。

### v5（当前，未提交）

- **单帧乘客不过滤**：用户反馈"只露 1 帧的乘客不能过滤"，`confirmed_ids` 改为包含所有出现过的 ID（`min_hits=1`），`total_count = len(gid_hits)`。欠计数是主要矛盾。
- **结果**：`tracking_output/20260829_006`，精确 5、±1 有 5、≥+2 有 2（+2, +1, +1）。
- **改善**：`20260715134221208` 从 v4 的 0 → +1（欠计数 2 人救回）；`20260715071110945`/`20260715132934340` 保住精确。
- **代价**：`20260715081444132` +1→+2、`20260715175447965` 0→+1（单帧误检/ID 碎片被计入，过计数回升）。

### v6（当前，未提交）

- **tracklet 合并（治 ID 分裂）**：v5 的 +2 过计数来自 ID 分裂（同一人跨帧关联失败被给两个 ID）。序列结束后离线合并：同窗 + 时间相邻（重叠≤MERGE_MAX_GAP）+ 窗内 rel_x 接近（<0.12）+ 外观相似（>0.80）的 tracklet 用并查集合并。
- **实现**：`MotionCoherentTracker` 新增 `tracklet_info`（每 gid 记录帧/rel_x/外观特征）和 `merge_tracklets()`；`process_sequence` 末尾调用，用合并后计数。
- **结果**：`tracking_output/20260829_009`，精确 4、±1 有 7、≥+2 有 1（+2）。
- **改善**：`20260715071110945` -1→0、`20260715132934340` +1→0（误合并修复 + 合并有效）。
- **局限**：`20260715081444132` 仍 +2——其分裂根因是**检测框位置不稳定**（同一人 rel_x 从 0.61 漂到 0.22，透视/抖动），非简单时间断裂，位置类合并判据覆盖不了。

## 最优基线选择

**判断标准：准确计数（预测 vs 人工核实人数）。**

- **v3（20260828_014）= 最优计数基线**：精确 6、±1 有 5、≥+2 有 1（+1），无极端误差。
- **v5（20260829_006）= 当前版本**：欠计数改善（单帧真乘客计入），但过计数回升（+2），准确计数略逊于 v3。

**选型建议**：
- 若**首要目标是准确计数**（超员检测业务核心）→ 用 **v3**（20260828_014）。
- 若**首要目标是消除过计数 + ID 稳定**，可接受 -1 欠计数 → 用 **v4**（20260829_005）。
- 若**首要目标是补欠计数**（不漏报遮挡乘客）→ 用 **v5/v6**（20260829_006/009）。

**下一优化方向**（针对 v6 残留的 `20260715081444132` +2）：其分裂根因是**检测框位置不稳定**（同一人 rel_x 透视/抖动下从 0.61 漂到 0.22），位置类合并判据覆盖不了。可考虑：① 合并判据用"帧间位移补偿后的位置"而非绝对 rel_x（抗透视漂移）；② 在检测端抑制"同一窗内 rel_x 快速漂移"的重复框；③ 若该序列属极端个案，可接受 +2（在 12 序列中仅 1 例）。

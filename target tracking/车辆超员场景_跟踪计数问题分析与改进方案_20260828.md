# 车辆超员场景 跟踪计数问题分析与改进方案

_对象：`target tracking/track_3class_window_bind.py`（D 方案 v3）· 2026-08-28_

> 本报告记录 D 方案 v3（`tracking_output/20260828_014`）实测 12 序列后，用户观察到的三类计数/跟踪问题（欠计数、过计数、人头 ID 跳变）的根因定位，以及改进方案选型（缝合模块 vs 官方 DeepSORT/BoT-SORT）。

---

## 📋 摘要

当前 D 方案 v3 在 12 序列上成绩为：精确 6、±1 有 5、≥+2 有 1（+1）。但存在三类残余问题：

1. **欠计数**：遮挡导致目标极小、只露极小一部分，模型没检测出来。
2. **过计数**：反光的头枕、玻璃等被误识别为 head。
3. **人头 ID 跳变**：OSNet 判别不够准，聚集时前后帧明显不同目标，但 ID 仍跳到同窗另一个目标。

这三类问题**分别落在不同层**（检测召回、检测误检+轨迹生命周期、关联+外观判别），不能靠单一模块解决。本报告逐层定位，并给出"在当前脚本基础上缝合标准模块 + 场景先验"的推荐方案。

---

## 🎯 三层问题定位

| 问题 | 责任层 | 本质 | 现有代码弱点 |
| --- | --- | --- | --- |
| 欠计数 | 检测召回 | 遮挡/小目标，模型没框出来 | `imgsz=640` 下头目标太小，特征不足 |
| 过计数 | 检测误检 + 轨迹生命周期 | 头枕/反光被当成 head，且新检测一出现即计入 | `pred=len(gid_hits)` 无生命周期过滤，新 ID 立即计数 |
| ID 跳变 | 关联 + 外观判别 | OSNet 分不清相似头 + 贪心匹配 + 聚集时位置分失效 | 贪心最近邻 + 软阈值，聚集时易串 ID |

**三个问题需要三种不同层的解法**，任何单一模块（包括官方跟踪器）都无法同时解决。

---

## 🔍 问题一：欠计数（遮挡/小目标漏检）

### 现象与根因

- 夜间/遮挡下，头部只露出极小一部分，`imgsz=640` 推理时目标在特征图里只有几个像素，模型未检出。
- 跟踪器只能跟踪"检测到"的人，漏检的人物理上无法凭空补出。
- 剩余误差以 -1 为主（每车漏 1 人），源头是检测 coverage。

### 解法（按性价比）

**① 车框 ROI 放大检测（最有效，改动小）**
- 先框出车 ROI，裁出车区域后放大（如 2-3 倍）再跑检测。
- 头在特征图里变大 2-3 倍，遮挡/小头召回显著提升。
- 针对"侧视车辆、头是小目标"最对症，无需重训。

**② 高分框 + 低分框两级关联（ByteTrack 思想）**
- `predict` 用低 conf（0.1）多检，再分组：
  - 高分框（conf≥0.35）：可建新轨迹 + 关联。
  - 低分框（0.1-0.35）：**只延续已存在轨迹，绝不新建 ID**。
- 这样"只露极小一部分"的低分真头能接续到已知的人（补欠计数），又不会把误检变成新 ID。

**③ 提高推理 imgsz（640→960）**
- 简单粗暴但比 ROI 放大慢，作备选。

> **诚实边界**：完全被遮挡（一点没露）的头物理不可见，任何方法都数不出。但"只露极小一部分"用 ①+② 可明显改善。

---

## 🔍 问题二：过计数（头枕/玻璃反光误检）

### 现象与根因

- 头枕、车内反光被检测成 head，且当前 `pred=len(gid_hits)`，**新检测一出现就计入**。
- 曾见单窗攒 4-6 个 ID（如 `20260715073655824` 窗 1 曾有 6 人）。

### 解法

**① 轨迹确认机制（Tentative→Confirmed），重新做对**
- 之前试过 `min_hits=2` 造成 pred 滞后（用户反馈"h5 出现但 pred 还是 5"）——**那是实现错了**，不是方向错。
- 正确做法：新轨迹先标记 **Tentative（不计数）**，连续观测 ≥2 帧转 **Confirmed 才计入 pred**。
- 头枕/反光通常是 1-2 帧闪现即消失 → 永远到不了 Confirmed → 不过计数。
- 渲染区分：Tentative 框用不同颜色或带"?"，Confirmed 正常。pred 显示"已确认人数"语义更准。

**② 座位槽硬约束（每窗人数上限）**
- 已有**方向感知窗槽位**（前窗=槽0、中窗=槽1、后窗=槽2），每窗物理座位数有限（前排≤3、中排≤3、后排≤3）。
- **每窗允许 Confirmed 轨迹数 ≤ 座位数**。窗已满时新检测落进去 → 大概率误检/重复 → 抑制不建新 ID。
- 结构性消灭"窗攒 4-6 个 ID"。

**③ 新轨迹创建阈值**
- 只有 conf≥0.35 的检测允许**创建新轨迹**；低分框只延续。头枕/反光误检分数往往不高，源头过滤。

> 过计数三招配合：确认机制（过滤闪现误检）+ 座位槽（硬上限）+ 高分才建新轨迹（源头过滤）。

## 🔍 问题三：人头 ID 跳变（OSNet 判别不足）

### 现象与根因

- 三人挤一窗时，位置近、外观像，A 的框下一帧跳到 B 的 ID。
- 核心：**OSNet 判别力不足 + 贪心匹配 + 聚集时位置分失效**。

### 解法（关键在"结构性约束"，不是换更强 ReID）

**① 窗内顺序保持（最对症，与窗槽位同理）**
- 短序列里同窗乘客**从左到右的顺序基本不变**（人不换座）。
- 约束：窗内按 `rel_x` 排序，**每个人"窗内排名"跨帧不变**，关联时强制"排名 k 检测配排名 k 轨迹"，不允许交叉。
- 结构性防止相邻两人 ID 互换——外观再像、位置再近，顺序锁死 ID 就串不了。与"窗用离车头槽位"同一思路。

**② 匈牙利全局最优匹配（替代贪心）**
- 当前贪心按分数排序逐个抢，一个轨迹被抢后另一检测只能找次优 → 聚集易串。
- 换成匈牙利（`ultralytics/trackers/utils/matching.py::linear_assignment`）全局一对一，杜绝抢 ID。

**③ 卡尔曼滤波（位置通道更稳）**
- 当前预测用"上次位置 + 速度"，噪声大。换卡尔曼（`KalmanFilterXYAH`）位置预测更平滑 → 位置分更可靠。

**④ OSNet 降权 + 输入质量修正**
- OSNet 作辅助而非主导，主靠窗内顺序 + 位置。
- 修正 BGR→RGB 转换（当前 `extract_feat` 喂 BGR，OSNet 按 RGB 预训练，特征系统性失真）。

> ID 跳变的根治不是"更强的外观"，而是**窗内顺序这个强结构先验**。人群越聚集，顺序约束越有价值。

## 🧩 方案选型：缝合模块 vs 官方 DeepSORT/BoT-SORT

### 结论：不建议整体换 DeepSORT/BoT-SORT，建议在现有脚本缝合标准模块 + 场景先验。

| 能力 | DeepSORT/BoT-SORT | 本场景需要 | 现有脚本 |
| --- | --- | --- | --- |
| 生命周期（Tentative→Confirmed→Lost→Removed） | ✅ | ✅ 治过计数 | ❌ 缺 |
| 匈牙利全局匹配 | ✅ | ✅ 治 ID 跳变 | ❌ 贪心 |
| 两级关联（ByteTrack 低分延续） | ✅ BoT-SORT 有 | ✅ 治欠计数 | ❌ 缺 |
| **窗口绑定**（ID 不跨窗） | ❌ 无 | ✅ 必须 | ✅ 已有 |
| **窗内顺序保持**（治聚集跳 ID） | ❌ 无 | ✅ 必须 | ❌ 缺 |
| **座位槽上限**（治过计数） | ❌ 无 | ✅ 必须 | ❌ 缺 |
| **车头方向/窗槽位**（治窗 ID） | ❌ 无 | ✅ 必须 | ✅ 已有 |
| 外观 ReID | OSNet 类 | **同样判别不足** | OSNet |

**为什么不全换**：
- DeepSORT/BoT-SORT 的强项（生命周期、匈牙利、两级关联）可**缝合进现有脚本**。
- 它们**没有**本场景关键先验（窗口绑定、窗内顺序、座位槽、车头方向），换过去都要重新加回。
- 它们的外观模型与 OSNet 同类，**换过去也解决不了"相似人头判别"**。

**BoT-SORT 唯一额外价值**是 ByteTrack 两级关联，但那只是一个模块，缝合进来即可。

## 🏗️ 推荐落地架构（缝合后）

```
检测
  ├─ predict conf=0.1 → 分高分框(≥0.35) / 低分框
  ├─ 高分框：可建新轨迹 + 关联
  └─ 低分框：只延续已有轨迹（不建新ID）
  （可选：车 ROI 放大后检测，补小目标召回）

跟踪（MotionCoherentTracker 增强）
  ├─ 窗口绑定（已有，保留）
  ├─ 窗内顺序保持（新增：rel_x 排名不可交换）← 治ID跳变
  ├─ 匈牙利全局匹配（新增，替换贪心）← 治ID跳变
  ├─ 卡尔曼滤波（新增，替换简单速度预测）← 治位置漂移
  └─ 座位槽上限（新增：每窗最多N个Confirmed）← 治过计数

生命周期（新增）
  ├─ Tentative（不计数）→ Confirmed（连续≥2帧）→ Lost → Removed
  ├─ 只统计 Confirmed 唯一 ID = pred
  └─ 渲染：Tentative 用不同颜色/带"?"，Confirmed 正常

计数
  └─ pred = Confirmed 唯一 ID 数（不再用 len(gid_hits) 全算）
```

### 实施顺序（每步可单独验证）

| 步骤 | 内容 | 对症问题 | 工作量 |
| --- | --- | --- | ---: |
| 1 | 窗内顺序保持 + 匈牙利全局匹配 | ID 跳变（最头疼） | 0.5-1 天 |
| 2 | 确认机制 + 座位槽上限 | 过计数 | 0.5-1 天 |
| 3 | 两级关联 + 车 ROI 放大 | 欠计数 | 1 天 |
| 4 | 整套回归 12 序列对比 | 全部 | 0.5 天 |

### 关键代码位置速查

| 位置 | 内容 |
| --- | --- |
| `track_3class_window_bind.py` `MotionCoherentTracker.update` | 阶段一贪心匹配（改匈牙利）+ 阶段二兜底 |
| `track_3class_window_bind.py` `WindowTracker` | 窗槽位（车头方向），可复用思路到窗内顺序 |
| `track_3class_window_bind.py` `extract_feat` | OSNet 特征，需修正 BGR→RGB |

## ✅ 验收标准

- **欠计数**：12 序列剩余 -1 数量下降（目标：全部 ≤±1，精确数 ≥8）。
- **过计数**：无 +2 以上；单窗 Confirmed 人数 ≤ 座位数。
- **ID 跳变**：聚集帧（同窗≥3 人）无相邻目标 ID 互换；窗内顺序约束下"排名 k"全程稳定。
- **不回归**：车窗 ID 物理稳定（前/中/后窗槽位不变）、首帧框窗、每窗人数实时、pred 不滞后。

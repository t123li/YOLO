# 车辆超员场景 跟踪计数问题分析与改进方案

_对象：`target tracking/track_3class_window_bind.py`（D 方案 v3）· 2026-08-28_

> 本报告记录 D 方案 v3（`tracking_output/20260828_014`）实测 12 序列后，用户观察到的三类计数/跟踪问题（欠计数、过计数、人头 ID 跳变）的根因定位，以及改进方案选型（缝合模块 vs 官方 DeepSORT/BoT-SORT）。

---

## 📋 摘要

当前 D 方案 v3 在 12 序列上成绩为：精确 6、±1 有 5、≥+2 有 1（+1）。但存在三类残余问题：

1. **欠计数**：遮挡导致目标极小、只露极小一部分，模型没检测出来。
2. **过计数**：反光的头枕、玻璃等被误识别为 head。
3. **人头 ID 跳变**：OSNet 判别不够准，聚集时前后帧明显不同目标，但 ID 仍跳到同窗另一个目标。

这三类问题**分别落在不同层**（检测召回、检测误检+轨迹生命周期、关联+外观判别），不能靠单一模块解决。本报告逐层定位，并给出"在当前脚本基础上缝合标准模块 + 场景先验"的推荐方案。**其中欠计数/过计数同时有模型侧根因**——本报告新增"检测模型改进"章节，覆盖 yolov8s 模型结构改进与 `train_3class.py` 训练参数改进。

---

## 🎯 三层问题定位

| 问题 | 责任层 | 本质 | 现有代码弱点 |
| --- | --- | --- | --- |
| 欠计数 | 检测召回 | 遮挡/小目标，模型没框出来 | `imgsz=640` 下头目标太小，特征不足 |
| 过计数 | 检测误检 + 轨迹生命周期 | 头枕/反光被当成 head，且新检测一出现即计入 | `pred=len(gid_hits)` 无生命周期过滤，新 ID 立即计数 |
| ID 跳变 | 关联 + 外观判别 | OSNet 分不清相似头 + 贪心匹配 + 聚集时位置分失效 | 贪心最近邻 + 软阈值，聚集时易串 ID |

**三个问题需要三种不同层的解法**，任何单一模块（包括官方跟踪器）都无法同时解决。

---

## 🧠 检测模型改进（欠计数/过计数的模型侧根因）

> 欠计数和过计数**不只是跟踪端问题，训练出的检测模型本身也有责任**。当前 3 类模型基于 `yolov8s` 训练（`target detection/train_3class.py`，`imgsz=640`、`batch=32`、`epochs=100`、`yolov8s.pt` 起步、COCO 预训练），模型对遮挡/小目标头部召回不足（欠计数）、对头枕/反光误检（过计数）。本节省略跟踪端，只谈"如何改进 yolov8s 模型本身 + 如何改进训练脚本参数"。

### 2.1 现状：train_3class.py 的训练配置

> 当前 3 类模型实际训练产物在 `target detection/run_3class/`（`run_3class/args.yaml` 确认配置）。

| 参数 | 当前值 | 分析 |
| --- | --- | --- |
| 基座 | `yolov8s.pt`（COCO 预训练） | s 是轻量级，小目标 head 特征弱；COCO 有 car 类先验但没有 head_shoulder 类 |
| `imgsz` | 640 | head 目标小，640 下特征不足 |
| `batch` | 32 | 4090 24G 适配，合理 |
| `epochs` | 100 | 偏低，可能未充分收敛 |
| `patience` | 100 | 几乎等于 epochs，早停未起作用 |
| `close_mosaic` | 10 | 默认，最后 10 轮关 mosaic |
| `cls_remap` | true | 已启用 COCO→自定义类重映射（合理） |
| `optimizer` | auto | 自动选优化器（合理） |
| `data` | 3 类序列级划分 | 需确认各类别样本量/类别平衡 |
| 无数据增强定制 | 默认 | 对遮挡/小目标无针对性增强 |

**从聚合指标看，检测模型相当不错、甚至接近饱和。但跟踪端结果一般，两者不矛盾，原因见 2.1.2。**

### 2.1.1b 模型结构决策结论（换不换 yolov8m/l / 改不改模块）

**结论：现阶段不改模型结构，不换 yolov8m/l，不动 yolov8s 内部模块。** 依据：

1. **指标已接近饱和**：mAP50=0.988、recall=0.970。换大模型/加 DCNv2/P2 层/注意力，是在剩余 3% 漏检里抠，边际收益极低，且搭上几小时云端重训。
2. **三个问题的瓶颈在跟踪端，不在检测**：
   - 欠计数：recall 已 0.97，剩余漏检是"完全遮挡的头"（物理不可见，换模型也救不了）+ 少量小头。跟踪端低分延续 + 车 ROI 放大性价比更高。
   - 过计数：precision 已 0.967，误检不多。真正问题是这些**少量误检被跟踪器当新 ID 计入**——是生命周期/座位槽的事。
   - ID 跳变：检测框再准也解决不了"两个相似头谁是谁"，是纯跟踪问题。
3. **诚实的补充**：per-size AP 未单独拿到（ultralytics 8.4.116 的 `Metric` 不暴露 `ap50_s/m/l`）。"模型对小头够强"是**基于整体 recall=0.97 的推断**，不是逐类确认。若要验证，可看 head 类单独的 AP50/AP50-95。

**触发"回头改模型"的条件**：跟踪端改进做完后，若仍残留明显的"小头漏检"，优先试 `imgsz=960 + epochs=250`（低成本训练改动，比换结构划算），而不是直接换 yolov8m/l。

### 2.1.2 为什么"指标不错"但"跟踪结果一般"

**核心：mAP/recall 是"单帧、聚合"指标，衡量的是"这一帧有没有把真实目标框出来"，而跟踪好坏是"跨帧、逐目标"问题。两者测的不是同一件事。** 具体拆解：

| 指标测不到的东西 | 为什么跟踪就翻车 |
| --- | --- |
| **跨帧一致性**：mAP 只看单帧框得准不准，完全不管"同一人前后帧是不是同一个框" | 跟踪的核心是 ID 跨帧绑定，聚集时两人互换 ID，单帧 mAP 完全不受影响，仍是高分 |
| **困难帧被平均掩盖**：mAP 是全部帧/全部目标的平均，简单帧（车正对、头清晰）把分拉高，遮挡/聚集/小头的困难帧的短板被稀释 | 欠计数恰恰发生在困难帧（遮挡小头漏检），平均 recall=0.958 掩盖了这些帧 recall 可能只有 0.6-0.7 |
| **误检的 conf 分布**：mAP 的 PR 曲线容忍"低分误检"（曲线下面积大），而跟踪里低分误检（头枕/反光 conf 0.2-0.4）会真的建 ID、污染计数 | 过计数源头就是这些"mAP 不惩罚但跟踪会记"的低分误检 |
| **同类可区分性**：mAP 不管"两个同类目标能不能区分开"，只管"框有没有覆盖到" | 聚集时两个相似头，检测能框出 2 个（mAP 满分），但跟踪分不清谁是谁 → ID 跳变 |
| **框位置抖动**：mAP50 容差 0.5 很宽松，框偏几个像素也算对 | 跟踪靠位置做关联，聚集时框抖动几个像素就可能匹配到邻座 → ID 串 |

**一句话结论**：mAP=0.98 说明"检测模型能框出目标"，但跟踪需要的是"跨帧稳定地区分每个目标"——后者还依赖检测在困难帧的召回、误检的 conf 分布、以及同类目标的可区分性，这些**聚合检测指标都不衡量**。所以检测指标高 ≠ 跟踪好，两者是不同层面的评价。

**对改进的启示**：
- 不能只看 mAP 就说"检测没问题"——要**按困难帧（遮挡/小头/聚集）分组看 recall**，以及**看低 conf 段的误检率**。
- 检测指标改进（2.2/2.3）能提高困难帧召回、压低分误检，直接帮助跟踪；但 ID 跳变的根治还要靠跟踪端（窗内顺序、匈牙利、卡尔曼）。
- 建议训练脚本在 val 时**额外输出按目标尺寸（小/中/大）和按 conf 分段的指标**，才能暴露"聚合指标掩盖的短板"。

### 2.2 模型结构改进（针对小目标/遮挡 head）

**① 换更大的基座或可变形卷积**
- `yolov8s` → **`yolov8m` 或 `yolov8l`**：更大模型对小目标特征更强，代价是推理变慢（本场景离线视频，可接受）。
- 或在 Neck 加 **DCNv2（可变形卷积）**：对形状变化/遮挡的 head 更鲁棒，是行人检测 SOTA 常用技巧。

**② 小目标专用 head / P2 层**
- YOLOv8 默认从 P3（stride 8）开始检测。小目标 head 常需要 **P2 层（stride 4）** 帮助，或用 **YOLOv8-P2 变体**。
- head 目标在 `imgsz=640` 下可能 <8px，P2 层能直接提升小目标召回。

**③ 涨点模块（注意力/特征融合）**
- Neck 加 **BiFPN / GFPN**（加权双向特征融合），比 PAN 更利于小目标。
- Backbone 加 **CA（坐标注意力）/ EMA** 等轻量注意力，增强对遮挡小目标的关注。
- 这些是目标检测"涨点"文献的常用手段（详见 `target detection/文献调研_车辆超员检测目标检测涨点_20260826/`）。

### 2.3 训练脚本参数改进（train_3class.py 可改）

**① 提高 `imgsz`：640 → 960**
- 头目标在 960 下特征面积约为 640 的 2.25 倍，小头召回提升。
- 代价：显存/推理变慢，但离线可接受。

**② 增加 `epochs`：100 → 200-300**
- 配合 `patience`（早停）防止过拟合；当前 100 可能未收敛充分。

**③ 多尺度训练（Mosaic/MixUp 增强 + 随机尺度）**
- ultralytics 默认开 Mosaic，可调 `mosaic=1.0`、`mixup=0.1-0.3`。
- 训练时随机 `imgsz`（如 640-960）能提升尺度鲁棒性，尤其对小头。
- 设 `rect=True`（矩形训练）可减少 padding，利于小目标。

**④ 类别不均衡处理**
- 3 类里 head 是小目标、样本可能少于 car/window。检查 `data.yaml` 各类数量：
  - head 少 → 加重 head 类损失（`cls` 权重）或对 head 类做复制增强（`copy_paste`）。
  - 用 **focal loss**（`loss_cls`）缓解难例/类别不平衡。

**⑤ 数据增强针对遮挡**
- 开启/加大 `hsv_h/v/s` 微调（夜间红外场景光照变化）。
- `translate/scale/fliplr` 增强遮挡角度多样性。
- 对 head 目标补更多"半遮挡"样本（人工裁剪遮挡的正样本）。

**⑥ 验证时用更高 imgsz**
- 训练 640、验证/推理 960 常有涨点（train_3class.py 里 `m.val(imgsz=IMGSZ)` 可提到 960）。

### 2.4 训练脚本的推荐改动（可直接落到 train_3class.py）

```python
EPOCHS = 250          # 100 → 250（配合早停）
IMGSZ = 960           # 640 → 960（小目标涨点最直接）
BATCH = 16            # 32 → 16（960 下显存翻倍，4090 需降）
NAME = "run_3class_v2"

model.train(
    data=DATA, epochs=EPOCHS, batch=BATCH, imgsz=IMGSZ,
    mosaic=1.0, mixup=0.2, close_mosaic=10,   # 增强
    patience=50,                              # 早停
    seed=0, device=0,
    # 可选：加 COCO 预训练不覆盖 car 类权重
)
```

> **注意**：这是"训练策略"改动，先改 `imgsz=960 + epochs=250` 验证是否涨点；再逐步加注意力/换基座（2.2）。每次改动在**同一序列级验证集**上回归，避免污染对比。

### 2.5 检测模型改进 vs 跟踪端改进的关系

- **欠计数**：模型召回（2.2/2.3）与跟踪端低分延续（问题一 ②）**互补**——模型能检出的头更多，跟踪端能把低分接续到已知人。
- **过计数**：模型误检（2.2 判别力）与跟踪端生命周期/座位槽（问题二）**互补**——模型误检少，跟踪端确认机制兜底。
- 建议顺序：**先改训练（低成本、一次投入）**，验证模型 mAP/recall 提升后，再叠加跟踪端模块。

## 🔍 问题一：欠计数（遮挡/小目标漏检）

### 现象与根因

- 夜间/遮挡下，头部只露出极小一部分，`imgsz=640` 推理时目标在特征图里只有几个像素，模型未检出。
- 跟踪器只能跟踪"检测到"的人，漏检的人物理上无法凭空补出。
- 剩余误差以 -1 为主（每车漏 1 人），源头是检测 coverage。

### 解法（按性价比）

**① 车框 ROI 放大检测（最有效，改动小）**
- 先框出车 ROI，裁出车区域后放大（如 2-3 倍）再跑检测。
- 头在特征图里变大 2-3 倍，遮挡/小头召回显著提升。
- 针对"侧视车辆、头是小目标"最对症，无需重训。

**② 高分框 + 低分框两级关联（ByteTrack 思想）**
- `predict` 用低 conf（0.1）多检，再分组：
  - 高分框（conf≥0.35）：可建新轨迹 + 关联。
  - 低分框（0.1-0.35）：**只延续已存在轨迹，绝不新建 ID**。
- 这样"只露极小一部分"的低分真头能接续到已知的人（补欠计数），又不会把误检变成新 ID。

**③ 提高推理 imgsz（640→960）**
- 简单粗暴但比 ROI 放大慢，作备选。

> **诚实边界**：完全被遮挡（一点没露）的头物理不可见，任何方法都数不出。但"只露极小一部分"用 ①+② 可明显改善。

## 🔍 问题二：过计数（头枕/玻璃反光误检）

### 现象与根因

- 头枕、车内反光被检测成 head，且当前 `pred=len(gid_hits)`，**新检测一出现就计入**。
- 曾见单窗攒 4-6 个 ID（如 `20260715073655824` 窗 1 曾有 6 人）。

### 解法

**① 轨迹确认机制（Tentative→Confirmed），重新做对**
- 之前试过 `min_hits=2` 造成 pred 滞后（用户反馈"h5 出现但 pred 还是 5"）——**那是实现错了**，不是方向错。
- 正确做法：新轨迹先标记 **Tentative（不计数）**，连续观测 ≥2 帧转 **Confirmed 才计入 pred**。
- 头枕/反光通常是 1-2 帧闪现即消失 → 永远到不了 Confirmed → 不过计数。
- 渲染区分：Tentative 框用不同颜色或带"?"，Confirmed 正常。pred 显示"已确认人数"语义更准。

**② 座位槽硬约束（每窗人数上限）**
- 已有**方向感知窗槽位**（前窗=槽0、中窗=槽1、后窗=槽2），每窗物理座位数有限（前排≤3、中排≤3、后排≤3）。
- **每窗允许 Confirmed 轨迹数 ≤ 座位数**。窗已满时新检测落进去 → 大概率误检/重复 → 抑制不建新 ID。
- 结构性消灭"窗攒 4-6 个 ID"。

**③ 新轨迹创建阈值**
- 只有 conf≥0.35 的检测允许**创建新轨迹**；低分框只延续。头枕/反光误检分数往往不高，源头过滤。

> 过计数三招配合：确认机制（过滤闪现误检）+ 座位槽（硬上限）+ 高分才建新轨迹（源头过滤）。

## 🔍 问题三：人头 ID 跳变（OSNet 判别不足）

### 现象与根因

- 三人挤一窗时，位置近、外观像，A 的框下一帧跳到 B 的 ID。
- 核心：**OSNet 判别力不足 + 贪心匹配 + 聚集时位置分失效**。

### 解法（关键在"结构性约束"，不是换更强 ReID）

**① 窗内顺序保持（最对症，与窗槽位同理）**
- 短序列里同窗乘客**从左到右的顺序基本不变**（人不换座）。
- 约束：窗内按 `rel_x` 排序，**每个人"窗内排名"跨帧不变**，关联时强制"排名 k 检测配排名 k 轨迹"，不允许交叉。
- 结构性防止相邻两人 ID 互换——外观再像、位置再近，顺序锁死 ID 就串不了。与"窗用离车头槽位"同一思路。

**② 匈牙利全局最优匹配（替代贪心）**
- 当前贪心按分数排序逐个抢，一个轨迹被抢后另一检测只能找次优 → 聚集易串。
- 换成匈牙利（`ultralytics/trackers/utils/matching.py::linear_assignment`）全局一对一，杜绝抢 ID。

**③ 卡尔曼滤波（位置通道更稳）**
- 当前预测用"上次位置 + 速度"，噪声大。换卡尔曼（`KalmanFilterXYAH`）位置预测更平滑 → 位置分更可靠。

**④ OSNet 降权 + 输入质量修正**
- OSNet 作辅助而非主导，主靠窗内顺序 + 位置。
- 修正 BGR→RGB 转换（当前 `extract_feat` 喂 BGR，OSNet 按 RGB 预训练，特征系统性失真）。

> ID 跳变的根治不是"更强的外观"，而是**窗内顺序这个强结构先验**。人群越聚集，顺序约束越有价值。

## 🧩 方案选型：缝合模块 vs 官方 DeepSORT/BoT-SORT

### 结论：不建议整体换 DeepSORT/BoT-SORT，建议在现有脚本缝合标准模块 + 场景先验。

| 能力 | DeepSORT/BoT-SORT | 本场景需要 | 现有脚本 |
| --- | --- | --- | --- |
| 生命周期（Tentative→Confirmed→Lost→Removed） | ✅ | ✅ 治过计数 | ❌ 缺 |
| 匈牙利全局匹配 | ✅ | ✅ 治 ID 跳变 | ❌ 贪心 |
| 两级关联（ByteTrack 低分延续） | ✅ BoT-SORT 有 | ✅ 治欠计数 | ❌ 缺 |
| **窗口绑定**（ID 不跨窗） | ❌ 无 | ✅ 必须 | ✅ 已有 |
| **窗内顺序保持**（治聚集跳 ID） | ❌ 无 | ✅ 必须 | ❌ 缺 |
| **座位槽上限**（治过计数） | ❌ 无 | ✅ 必须 | ❌ 缺 |
| **车头方向/窗槽位**（治窗 ID） | ❌ 无 | ✅ 必须 | ✅ 已有 |
| 外观 ReID | OSNet 类 | **同样判别不足** | OSNet |

**为什么不全换**：
- DeepSORT/BoT-SORT 的强项（生命周期、匈牙利、两级关联）可**缝合进现有脚本**。
- 它们**没有**本场景关键先验（窗口绑定、窗内顺序、座位槽、车头方向），换过去都要重新加回。
- 它们的外观模型与 OSNet 同类，**换过去也解决不了"相似人头判别"**。

**BoT-SORT 唯一额外价值**是 ByteTrack 两级关联，但那只是一个模块，缝合进来即可。

## 🏗️ 推荐落地架构（缝合后）

```
检测
  ├─ predict conf=0.1 → 分高分框(≥0.35) / 低分框
  ├─ 高分框：可建新轨迹 + 关联
  └─ 低分框：只延续已有轨迹（不建新ID）
  （可选：车 ROI 放大后检测，补小目标召回）

跟踪（MotionCoherentTracker 增强）
  ├─ 窗口绑定（已有，保留）
  ├─ 窗内顺序保持（新增：rel_x 排名不可交换）← 治ID跳变
  ├─ 匈牙利全局匹配（新增，替换贪心）← 治ID跳变
  ├─ 卡尔曼滤波（新增，替换简单速度预测）← 治位置漂移
  └─ 座位槽上限（新增：每窗最多N个Confirmed）← 治过计数

生命周期（新增）
  ├─ Tentative（不计数）→ Confirmed（连续≥2帧）→ Lost → Removed
  ├─ 只统计 Confirmed 唯一 ID = pred
  └─ 渲染：Tentative 用不同颜色/带"?"，Confirmed 正常

计数
  └─ pred = Confirmed 唯一 ID 数（不再用 len(gid_hits) 全算）
```

## ✅ 验收标准

- **欠计数**：12 序列剩余 -1 数量下降（目标：全部 ≤±1，精确数 ≥8）。
- **过计数**：无 +2 以上；单窗 Confirmed 人数 ≤ 座位数。
- **ID 跳变**：聚集帧（同窗≥3 人）无相邻目标 ID 互换；窗内顺序约束下"排名 k"全程稳定。
- **不回归**：车窗 ID 物理稳定（前/中/后窗槽位不变）、首帧框窗、每窗人数实时、pred 不滞后。

# 车辆超员场景目标检测涨点计划

## 1. 最终建议

当前最值得优先做的不是增加一个注意力模块，而是依次完成以下四件事：

1. 把跟踪入口从单阈值 `conf=0.6` 改为检测低阈值加跟踪高低分二阶段使用，并在独立序列上扫描阈值。
2. 先检测车辆或使用已有车辆框，将车辆侧窗 ROI 裁出、适度扩边并缩放到 640/960 后再检测人头。
3. 建立按车辆或原始视频分组的冻结测试集，补充纯背景、空车、头枕、反光、后视镜和路边行人等难负样本。
4. 在完全相同的划分和训练协议下，优先比较 `YOLOv8m@960`、`YOLO26m@960` 和 P2 小目标头；`l` 是第二梯队，`x` 暂不建议。

模块改造只放在上述基线之后。首选顺序是 P2 检测头或更好的多尺度融合、BiFPN、Coordinate Attention；DCNv4 仅在导出和算子兼容性允许时做。不要同时加入两个以上模块，否则无法判断收益来源。

## 2. 当前基线诊断

### 2.1 已核验的训练信息

| 项目 | 当前值 |

| 训练轮数 | 100 epoch |
| 输入尺寸 | 640 |
| batch | 16 |
| 训练图像 | 15,913 |
| 验证图像 | 1,989 |
| 测试图像 | 1,990 |
| 训练实例 | 55,877 个 head |
| 验证实例 | 6,898 个 head |
| 测试实例 | 6,994 个 head |
| 最佳 mAP50 | 0.96063，epoch 77 |
| 最佳 mAP50-95 | 0.68920，epoch 76 |
| 最佳 Precision | 0.93804，epoch 93 |
| 最佳 Recall | 0.91650，epoch 84 |
| PR 图 mAP50 | 0.959 |
| 最佳 F1 阈值 | 约 0.346，F1 约 0.92 |
| 跟踪脚本检测阈值 | 0.6 |

### 2.2 关键问题

1. **阈值直接制造漏检。** 验证曲线的最佳 F1 置信度约为 0.346，而跟踪脚本使用 `CONF_THRES = 0.6`。跟踪不应只接收 0.6 以上检测；短时被遮挡、远距离、反光或模糊人头往往首先表现为分数下降。
2. **目标在网络输入上偏小。** 原图框宽高第 10/50/90 分位约为 `30×38 / 51×67 / 72×96 px`。原图约 1620×1080，等比例缩放到 640 后，第 10 分位只有约 `12×15 px`，中位数约 `20×26 px`。P2 特征、小目标标签分配和 ROI 放大都有明确依据。
3. **mAP50 与 mAP50-95 相差约 27 个百分点。** 单类别的“有没有头”已较强，但高 IoU 下定位质量仍是明显短板。应优先检查遮挡框标注一致性、输入分辨率、多尺度特征和框回归，而不是只优化分类置信度。
4. **数据没有纯负样本。** train/val/test 的每张图都至少有一个 head 标注。真实跟踪中存在空车、车窗反光、头枕、座椅、后视镜和车外行人，这些分布没有被充分约束。
5. **业务测试和训练分布可能不一致。** 已查看的测试样例中出现了带文字和检测框叠加的图像。必须确保训练、验证、测试使用原始无绘制图像，避免图像上的框线或文字成为捷径特征。
6. **当前指标不能代表跟踪计数。** 高 mAP 不等于连续帧不漏检，也不等于人数计数正确。检测、关联和计数要分别验收。

## 3. 先建立正确的评估协议

### 3.1 冻结数据划分

- 按原始视频、车辆或一次过车事件分组，禁止同一车辆的相邻帧跨 train/val/test。
- 推荐比例 70/15/15；若独立车辆数量少，至少保留一个完全不参与开发的 final test。
- 清理所有画过框、写过置信度、带调试文字的图像；只能用原始帧训练和评估。
- 保留现有测试集作 `legacy_test`，新建 `grouped_test` 和 `hard_test`，不要覆盖旧结果。

### 3.2 难例分层

为每个真值框增加可选属性，或至少生成分组清单：

- 输入后高度：`<16 px`、`16–32 px`、`>32 px`。
- 遮挡：无遮挡、轻度、重度。
- 亮度与反光：正常、过曝、强反光、极暗。
- 模糊：清晰、运动模糊、离焦。
- 车辆距离与位置：近/中/远，前排/后排，画面边缘/中心。

### 3.3 必报指标

检测层：

- AP50、AP75、AP50-95、Precision、Recall、F1、F2。
- `Recall@Precision>=0.95`，因为业务更关心在可接受误检下能找回多少人头。
- 按尺寸、遮挡、亮度和车辆距离分组的 Recall 与 AP。
- 每车漏检数、每千帧误检数，并保存 FP/FN 图册。

跟踪与计数层：

- DetA/HOTA、IDF1、ID switch、fragmentation。
- 每车人数 MAE、RMSE、完全正确率、欠计数率、过计数率。
- FPS、单帧延迟、显存峰值；全部在目标部署硬件上测。

统计要求：

- 初筛可用一个固定 seed；进入候选的模型至少跑 3 个 seed，报告均值与标准差。
- 最终比较用同一 test、同一阈值选择规则、同一图像尺寸和同一后处理。
- 阈值只能在验证集选择，不能在测试集上调。

## 4. P0：不重新训练即可执行的涨点实验

### 4.1 阈值和 NMS 扫描

在验证序列上保存原始预测，再离线扫描：

- `conf_low`: 0.05、0.10、0.15、0.20。
- `conf_high`: 0.35、0.40、0.45、0.50、0.60。
- NMS IoU：0.45、0.55、0.65、0.75。
- 输入：640、960、1280。

跟踪时建议：

- 高分框用于新建轨迹和第一阶段匹配。
- 低分框只能延续已确认轨迹，不允许新建 ID。
- 单帧低分候选不能直接计数；连续 2/3 帧确认后才计数。
- 初始搜索中心可从 `conf_low=0.10`、`conf_high=0.40` 开始，但最终值必须由验证集决定。

这一步的验收不是单看 F1，而是同时看欠计数率和误检轨迹数。

### 4.2 车辆 ROI 二阶段检测

现有画面中车辆只占全图的一部分。建议流程：

1. 用已有车辆检测结果或人工可用的车辆框获取车体 ROI。
2. 四周扩边 5%–10%，避免裁掉前后排边缘人头。
3. 若能稳定定位车窗，再裁侧窗联合 ROI；否则先使用整车上半部 ROI。
4. 将 ROI 等比例缩放并填充到 640 或 960，再做人头检测。
5. 将人头框映射回原图坐标后进入跟踪器。

相比全图 SAHI，车辆 ROI 更符合场景先验，计算量更可控，也减少树木、路灯和路边行人的干扰。只有车辆框不稳定或一帧多车、目标极远时，才比较 SAHI 切片。

### 4.3 可选推理增强

- TTA 只做上限实验，例如水平翻转和单一额外尺度；若增益不足 0.5 AP 或延迟翻倍，不部署。
- CLAHE、gamma 或去噪必须训练和推理一致。不要只在推理阶段强行增强，以免产生分布偏移。
- 对红外灰度图，颜色增强价值有限；应把预算放在亮度、对比度、噪声、模糊和过曝模拟。

## 5. P0/P1：数据侧改进

### 5.1 难负样本

新增不含 head 的图像，并保留空标签文件：

- 空车与关闭车窗。
- 头枕、座椅靠背、方向盘、后视镜、挂件。
- 车窗高光、灯光斑、路边树叶和路灯。
- 车外行人或骑行者经过车辆附近。
- 带强噪声、雨雾、运动模糊但无人头的帧。

建议从真实跟踪视频中用当前模型低阈值跑一遍，按最高误检分数排序人工审核，形成 hard-negative mining 闭环。第一轮可使负图占训练图像的 10%–20%，再根据 FP 变化调整。

### 5.2 漏检难例回灌

- 从 `conf=0.05` 的预测中收集未匹配真值和低分真阳性。
- 优先补充被 B 柱遮挡、后排只露部分头部、玻璃过曝、侧脸、低头和相邻双人。
- 统一“可见多少才标”的规则。对重遮挡目标，框应覆盖一致的可见区域或统一采用完整头部估计，不能混用。
- 训练集可抽帧去冗余，把标注预算用于新车辆、新距离和新光照，而不是继续增加几乎相同的相邻帧。

### 5.3 数据增强建议

保留：水平翻转、适度缩放、轻度平移、亮度/对比度、传感器噪声、轻度运动模糊。

谨慎使用：

- Mosaic：前期可用，最后 10–20 epoch 关闭；检查它是否制造不合理的小头。
- Copy-Paste：只复制带合理车窗上下文的人头，不要把裸头贴到车外背景。
- MixUp/CutMix：对小且遮挡的人头容易破坏局部纹理，优先级低。
- 旋转和透视：道路侧视相机几何稳定，只使用与真实抖动一致的小幅度。

## 6. P1：模型尺度与版本路线

### 6.1 为什么先选 m，不直接选 l/x

`s -> m` 通常是最有性价比的容量提升；`m -> l -> x` 的边际收益会下降，而显存、训练时间和延迟迅速增加。本项目只有一个类别且背景相对固定，过大的模型可能记住车辆和场景纹理，并不能自动解决遮挡和低分阈值问题。

推荐顺序：

1. `YOLOv8m@960`：最干净的同代容量/分辨率对照。
2. `YOLO26m@960`：当前仓库原生支持，STAL 明确面向小目标正样本覆盖，值得做主候选。
3. P2 版本：当 `<16 px` 组仍是主要瓶颈时比较 `yolov8m-p2` 或 `yolo26m-p2` 配置。
4. `YOLOv8l@960` 或 `YOLO26l@960`：只有 m 明显涨点且延迟余量足够时再做。
5. `RT-DETR`：作为 NMS-free 架构对照，尤其观察相邻人头是否被 NMS 互相抑制。

`YOLOv8x` 不列入首轮。若 m/l 都显示容量持续带来收益、训练没有过拟合且部署允许，再评估 x。

### 6.2 YOLO12、YOLO26 与 RT-DETR 的定位

- YOLO12 的 Area Attention 适合验证全局上下文是否帮助遮挡头部，但它较新，不应替代数据修复。
- YOLO26 的 STAL、小目标 P2 配置和原生端到端头与本问题更直接相关，优先级高于单独给 YOLOv8 堆注意力。
- RT-DETR 消除 NMS，可测试相邻人头抑制问题；但 DETR 的稀疏匹配并不保证小目标更强，因此只作为受控对照。
- YOLOv10 是重要的 NMS-free 里程碑，但当前工程已原生支持更新的 YOLO26，首轮没有必要同时训练两者。

## 7. P2：模块替换消融

只在最优标准模型上逐个加入模块，每次保持训练种子、增强、分辨率和优化器相同。

| 优先级 | 模块 | 放置建议 | 适用理由 | 风险 |
| --- | --- | --- | --- | --- |
| 1 | P2 检测头 | 从 stride 4 高分辨率特征增加一层预测 | 输入后大量头部小于 32 px | FLOPs 与显存增加，误检可能上升 |
| 2 | BiFPN | 替换/改造 neck 的跨尺度融合 | 高被引、多尺度融合证据强 | 不应与 P2 同轮同时加入 |
| 3 | Coordinate Attention | neck 后段或高分辨率分支少量插入 | 保留位置信息、开销较低 | 可能与现有特征重标定重复 |
| 4 | DCNv4 | neck 的一个高层或融合块做单点替换 | 对车窗形变、遮挡轮廓有潜力 | 自定义算子、Windows/ONNX/TensorRT 兼容风险高 |
| 5 | CBAM | 仅作传统注意力基线 | 成熟、实现简单 | 很多 YOLOv8 应用论文只报单数据集小幅增益，泛化证据弱 |
| 6 | NWD/RKA | 仅用于极小框的分配或回归消融 | IoU 对十几像素框位移过敏 | 会侵入损失和标签分配 owner，维护成本高 |

不建议首轮替换 GFL/VFL/DFL。YOLOv8 已使用 DFL 思路；重新组合 Varifocal 或 GFL 会同时改变质量评分、分类和框回归，难以把收益归因。若最终问题是“高分框定位差”，再做专门损失实验。

## 8. 推荐实验矩阵

### 阶段 A：零训练与评估修复

| 编号 | 改动 | 目的 | 晋级条件 |
| --- | --- | --- | --- |
| A0 | 当前 best.pt，复现 640 | 冻结真实基线 | 指标与现有结果一致 |
| A1 | conf/NMS 网格 | 找回低分真阳性 | Recall 和欠计数改善，FP 可控 |
| A2 | 960/1280 推理 | 测分辨率上限 | 小目标 Recall 明显改善 |
| A3 | 车辆 ROI@640/960 | 放大目标、去背景 | 比全图同延迟设置更优 |
| A4 | 高低分二阶段跟踪 | 用低分框续轨 | IDF1/计数 MAE 改善 |

### 阶段 B：标准模型比较

| 编号 | 模型 | 输入 | 说明 |
| --- | --- | ---: | --- |
| B0 | YOLOv8s | 640 | 在新划分上重训，作为公平基线 |
| B1 | YOLOv8m | 960 | 首选同代扩容 |
| B2 | YOLOv8l | 960 | 仅在 B1 有持续收益时 |
| B3 | YOLO26m | 960 | 首选新版本候选 |
| B4 | YOLO26m-P2 | 960 | 小目标组仍为主要瓶颈时 |
| B5 | RT-DETR-L 或硬件可承受型号 | 960 | NMS-free 架构对照 |

### 阶段 C：单模块消融

| 编号 | 基于阶段 B 最优模型 | 唯一改动 |
| --- | --- | --- |
| C1 | Best-B | BiFPN |
| C2 | Best-B | Coordinate Attention |
| C3 | Best-B | DCNv4 单点替换 |
| C4 | Best-B | NWD/RKA，仅当 `<16 px` 组定位失败明显 |

### 统一晋级门槛

候选相对公平基线至少满足：

- AP50-95 提升不少于 1.0 个百分点，或难例 Recall 提升不少于 1.5 个百分点。
- Precision 下降不超过 0.5 个百分点；若业务允许更低 Precision，须以计数 MAE 明显改善补偿。
- 每车欠计数率下降，且过计数率不显著增加。
- 3 个 seed 的平均提升大于标准差，不接受单次幸运结果。
- 延迟和显存满足部署预算；若尚无预算，先完整记录 Pareto 曲线，不提前定模型。

这些数值是工程晋级门槛，不是预先承诺的涨点幅度。

## 9. 训练配置模板

先复制并修正数据 YAML，使其指向按车辆/序列重划分后的数据。以下为实验模板，实际 batch 按显存保持等效 batch size：

```powershell
yolo detect train `
  model=yolov8m.pt `
  data="F:/车辆超员检测项目数据集/head_grouped/data.yaml" `
  imgsz=960 epochs=150 patience=30 `
  batch=-1 device=0 workers=4 `
  cos_lr=True close_mosaic=15 `
  project="F:/vehicle_dataset/runs_detection_ablation" `
  name="B1_yolov8m_960_seed0" seed=0 deterministic=True
```

YOLO26 对照：

```powershell
yolo detect train `
  model=yolo26m.pt `
  data="F:/车辆超员检测项目数据集/head_grouped/data.yaml" `
  imgsz=960 epochs=150 patience=30 `
  batch=-1 device=0 workers=4 `
  project="F:/vehicle_dataset/runs_detection_ablation" `
  name="B3_yolo26m_960_seed0" seed=0 deterministic=True
```

验证时保存 JSON 和图：

```powershell
yolo detect val `
  model="F:/vehicle_dataset/runs_detection_ablation/B3_yolo26m_960_seed0/weights/best.pt" `
  data="F:/车辆超员检测项目数据集/head_grouped/data.yaml" `
  split=test imgsz=960 conf=0.001 iou=0.7 `
  save_json=True plots=True
```

`conf=0.001` 用于生成完整 PR 曲线，不代表部署阈值。部署阈值应由验证集扫描后固定。

## 10. 两周可执行排期

### 第 1–2 天

- 建立按车辆/视频分组的 val/test。
- 清除带框和文字的输入图。
- 标注 300–500 帧连续跟踪验证集及每车人数真值。
- 建立尺寸、遮挡、反光、模糊分组。

### 第 3–4 天

- 复现 A0。
- 完成 conf/NMS/imgsz 扫描。
- 完成车辆 ROI 与全图对照。
- 输出 FP/FN 图册和按组 Recall。

### 第 5–8 天

- 训练 B0、B1、B3。
- 根据 B1/B3 的尺寸分组结果决定是否训练 B2/B4。
- 只保留达到晋级门槛的模型。

### 第 9–11 天

- 对最佳标准模型做 C1、C2；DCNv4 仅在部署链支持时做。
- 最优两个模型补跑 seed 1、2。

### 第 12–14 天

- 接入高低分二阶段跟踪。
- 在冻结序列上评估 IDF1、IDSW、计数 MAE 和完全正确率。
- 选择准确率—速度 Pareto 最优方案，导出并做目标硬件基准。

## 11. 最终决策规则

- 如果 A1/A4 已显著减少漏检：保留当前检测器或仅升级到 m，把精力放到跟踪状态机和难例数据。
- 如果 A3 显著提升：采用车辆 ROI，结构模块降级为次要优化。
- 如果 960 对小目标显著、m 与 l 差异很小：选择 m，不上 x。
- 如果 P2 只增加误检：回退 P2，增加难负样本并保留 ROI 放大。
- 如果 YOLO26m 在小目标 Recall、计数 MAE 和延迟上同时胜出：作为主模型；否则继续使用可复现、生态更稳的 YOLOv8m。
- 如果 RT-DETR 只改善相邻框但速度或小目标 Recall 较差：不部署，只把结果作为 NMS 诊断证据。
- 任一自定义模块不能同时通过准确率、稳定性和导出测试，立即删除而不是保留兼容分支。
